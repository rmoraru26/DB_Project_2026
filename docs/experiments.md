# Experiments and findings

Environment for every experiment below (all actually executed):

- MariaDB **13.0.2** official Windows x64 zip (`mariadb-13.0.2-winx64.zip`, SHA-256
  `ba9cefd6…5fb74`, verified), started from a fresh `mariadb-install-db` data directory,
  bound to 127.0.0.1.
- Windows 11 Pro, Intel Core i7-13700H, 32 GB RAM, NVMe SSD.
- `campus_audit.dll` built with Zig 0.16.0 (`plugin/build_windows.ps1`).
- Raw outputs: `docs/evidence/` (local paths replaced by `<scratch>`/`<repo>`).

| # | Setup | Expected | Observed | Interpretation |
|---|---|---|---|---|
| 1 | Skeleton audit plugin (counts events), declared EXPERIMENTAL, `INSTALL SONAME` on a default server | loads | **ER 1126** *"Loading of experimental plugin skel is prohibited by --plugin-maturity=gamma"*; with `plugin_maturity=experimental` it loads, is `ACTIVE`, counts events, unloads | Maturity is enforced at load time. campus_audit declares BETA and documents `plugin_maturity=beta`. The original `skel` plugin was not committed; `examples/skeleton_plugin/skeleton_audit.cpp` reproduces the refusal with committed code (built with `-DSKELETON_EXPERIMENTAL`, refused by `plugin_maturity=beta`, `12-skeleton-plugin.txt`) |
| 2 | Same workload (application booking, password-hash UPDATE, SELECT, failing INSERT, CREATE/DROP USER) under `server_audit` (CONNECT, QUERY_DML, QUERY_DDL, TABLE) and campus_audit | campus_audit adds schema filtering, per-table records joined to the statement's outcome, masking (both record the return code) | server_audit: raw SQL incl. `'pbkdf2:sha256:600000$SALTsalt$deadbeef'` and booking values; extra QUERY records for each trigger body; READ events on `mysql.table_stats/column_stats/index_stats`; 14 writes to `mysql.*` privilege tables for CREATE/DROP USER. campus_audit: only `university_resources`, literals masked, error code 4025 on the failing INSERT, nothing for the user management | What MariaDB did not do before for this use case: structured per-schema write audit with statement outcome and no data leakage, plus visible gaps |
| 3 | 2 000 single-row autocommit INSERTs, 5 repetitions each (+1 warm-up), `innodb_flush_log_at_trx_commit=2`, client wall time: no plugin / campus_audit (watching the schema) / server_audit (QUERY_DML,TABLE) | small overhead | medians **721 ms / 810 ms / 745 ms** (`docs/evidence/benchmark-windows.csv`); log volume for 12 000 statements: campus_audit 24 005 lines, **6.8 MB**; server_audit 24 001 lines, 2.3 MB (rotated over 3 files) | ≈ +12 % (≈ 45 µs per statement, 2 records) for campus_audit vs ≈ +3 % for server_audit on this micro-benchmark. campus_audit issues one unbuffered `write()` per record and writes self-describing JSON (~284 B/record). One machine, one workload: not a general performance claim |
| 4 | **Real write failure on Windows**: another process holds `FileStream.Lock(0, long.MaxValue)` on the active log for 25 s; 4 INSERTs during the lock, 1 after | statements succeed; loss visible | every INSERT succeeded (5 rows in the table); `Campus_audit_state=DEGRADED`, `write_failures=1`, `last_error="Write to audit log failed: Permission denied (errno 13)"`; **one** error-log line; a reopen attempt at +5 s failed silently (still locked); after unlock the next event reopened the file, wrote `{"event":"audit_gap","dropped_events":8,...}`, state `ACTIVE`, plus an error-log notice | Fail-open with explicit, quantified data loss; error log not flooded. `docs/evidence/exp-lock.txt` |

| 6 | `loose_campus_audit_file_path` in `my.ini` points to a missing directory; server restart | server starts, plugin off, clear reason | server up; plugin `NOT INSTALLED` in `ALL_PLUGINS`, still in `mysql.plugin`; error log: *"campus_audit: plugin not started: Cannot open audit log '…': No such file or directory (errno 2)"*, *"init function returned error"* – **and a spurious line from deinit** | **Finding: 13.0.2 calls deinit after a failed init** (`finalize_audit_plugin`). Fixed with an `initialized` guard; re-run with `loose_campus_audit_databases=bad name` shows only the intended lines (`docs/evidence/exp-startup.txt`) |
| 7 | Plugin installed with `INSTALL SONAME`, options in `my.ini`, server shutdown + start | plugin back, options applied | shutdown wrote `plugin_stop` (counters) to the old file; after start the plugin was `ACTIVE` from `mysql.plugin`, `file_path`, `connections=ALL`, `databases=university_resources,exp_db` came from `my.ini`, new instance id, `plugin_start` record | Restart and reload behave as documented; every instance is identifiable in the log |
| 8 | 8 concurrent clients × 50 INSERTs into a watched table | 400 + 400 records, no torn lines | 400 `table_write`, 400 `statement`, 0 invalid JSON lines, all `seq` unique (integration test) | Single `write()` per record under a mutex keeps lines whole |
| 9 | `START TRANSACTION; UPDATE …; ROLLBACK` on a watched table | ? | `table_write` + `statement status ok` recorded; value unchanged; no trigger row | The plugin records statements, not commits – documented limitation |
| 10 | Booking through the web app (account `campus_app`, `@app_user_id`) | trigger row and plugin records can be joined | `v_row_change_history` shows the trigger row (`application_user_id`, `event_source=application`) with the plugin's `query_id`, account `campus_app[campus_app] @ localhost` and digest; the trigger's own write appears as a second `table_write` on `audit_events` with the same `query_id` | The two mechanisms are complementary and correlate through `connection_id` |
| 11 | `INSTALL SONAME 'campus_audit'` while it is installed | error | silent success; `INSTALL PLUGIN campus_audit SONAME …` → ER 1968 | Undocumented-looking difference between the two statements; the demo script relies on the no-op |
| 12 | Failing INSERT (CHECK constraint) on `rooms` | ? | `table_write` for `rooms` **and** `audit_events`, statement `error_code 4025` | TABLE LOCK events happen before execution: "opened for write" ≠ "changed". `audit_events` is listed because the tables a trigger may write are locked in advance, although the trigger never runs |

project's Docker image based on `mariadb:13.0.2-resolute`), run on a private copy of the repository on
2026-11-03; logs and outputs in `docs/evidence/linux-ci-2026-11-03/`:

| # | Setup | Expected | Observed | Interpretation |
|---|---|---|---|---|
| 18 | `SET GLOBAL campus_audit_max_sql_length = 999999` as the first statement of a new connection, Linux (Docker), plugin 1.1.0 | clamped to 8192, as on Windows | no answer for an hour; nothing in the error log after the previous connection; the web container's health checks queued up (90 waiting) until the run was cancelled | Self-deadlock on `LOCK_global_system_variables`: the server holds it while it runs the update callback, and the callback's first THDVAR access of the session locks it again (`docs/plugin-api-notes.md`). Windows passed because its mutex is a `CRITICAL_SECTION`, which the owner may lock again. 1.1.1 keeps the mark in a thread-local flag; the same check then passed on Linux (CI run 2) and on Windows (`05-plugin-e2e-tests.txt`) |
| 19 | `LOAD_FILE()` of the plugin's log on Linux (Docker), without `campus_audit_readable_by_all` | the log's contents | NULL: `make demo` stopped with ER 1644 from `import_plugin_log`; 42 end-to-end checks reported "got: 0"; 8 app tests and 3 browser tests showed "Plugin log not imported" | `LOAD_FILE()` requires `S_IROTH`, and the plugin creates its log `0660` under the server's umask. With the startup option `campus_audit_readable_by_all = ON` (1.1.1, set in the Docker image) every import worked: the demo, 97 end-to-end checks, 104 app tests and 11 browser tests passed (CI run 4). ## Information available at the chosen callbacks

See the table in `docs/plugin-api-notes.md` §2.  Not recoverable by an audit plugin: row images,
rows affected, commit/rollback outcome of a statement, application-level identity, the tables of a
refused statement or of any statement from GENERAL events alone, the account a CHANGE_USER switched
(or tried to switch) to.
